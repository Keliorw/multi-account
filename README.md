# multi-account

Плагин для Claude Code: несколько аккаунтов Claude на одном компьютере, у каждого терминала свой,
при этом **memory, сессии, настройки и skills общие**.

- **Status line** — показывает, под каким аккаунтом открыт терминал. Текст выводится
  приглушённым цветом в конце строки подсказки под полем ввода:
  `👤 me@work.com [work] · Opus 5.5 · my-project`
- **Skill `setup-accounts`** — по просьбе «настрой второй аккаунт» сам создаёт профиль
  и команду для его запуска.

## Установка

В терминале, в сессии Claude Code:

```
/plugin install multi-account --marketplace Keliorw/multi-account
```

Дальше `y` — добавить маркетплейс, затем Enter — область **user** (плагин будет во всех проектах).
Status line появляется сразу, перезапуск не нужен.

Из локальной папки (до публикации на GitHub или для разработки):

```
/plugin install multi-account --marketplace ~/Projects/multi-account
```

## Настройка второго аккаунта

Попроси Claude в любой сессии:

> Настрой мне второй аккаунт Claude с именем work

Скилл создаст профиль и объяснит, что делать дальше. Вручную то же самое:

```bash
bash ~/.claude/plugins/…/skills/setup-accounts/setup-account.sh work   # путь покажет /plugin
```

Потом:

1. Открой новый терминал и запусти `claude-work`.
2. Выполни там `/login` вторым аккаунтом.
3. Проверь `/status` в обоих терминалах: email должен быть разный.
   В status line у дополнительного профиля рядом с email стоит `[work]`.

Основной аккаунт по-прежнему запускается командой `claude`.

| Команда | Что делает |
| --- | --- |
| `setup-account.sh <name>` | создать профиль `~/.claude-<name>` и команду `claude-<name>` |
| `setup-account.sh --list` | показать профили и их email |
| `setup-account.sh --remove <name>` | удалить профиль: только его вход и команду, общие данные остаются |

## Как это устроено

Каждый профиль — это отдельная папка конфига (`CLAUDE_CONFIG_DIR=~/.claude-<name>`) со своей
авторизацией: `.credentials.json` и `.claude.json`. Всё, что от аккаунта не зависит,
подключено симлинками к основному `~/.claude`:

| Общее (симлинк) | Своё у профиля |
| --- | --- |
| `projects/` — memory и транскрипты сессий | `.credentials.json` — токены входа |
| `settings.json`, `CLAUDE.md`, `keybindings.json` | `.claude.json` — аккаунт и кэши. MCP-серверы и настройки проектов копируются один раз при создании |
| `skills/`, `commands/`, `agents/`, `plugins/`, `hooks/`, `output-styles/` | служебные папки: кэш, логи, телеметрия |
| `history.jsonl`, `file-history/` | |

Плагины тоже общие, поэтому status line работает во всех профилях. Отдельная запись
`statusLine` в `settings.json` не нужна. Если она уже есть, её можно убрать, чтобы строка
не дублировалась.

Status line берёт email из `.claude.json` активной папки конфига и обновляется на старте
сессии, после каждого ответа и раз в 15 секунд. Поэтому `/login` и `/model` подхватываются
без перезапуска.

## Продолжить разговор под другим аккаунтом

Сессии общие, поэтому разговор из одного терминала можно продолжить в другом:

```bash
claude-work -c    # последняя сессия
claude-work -r    # выбрать из списка
```

Одну и ту же сессию не держи открытой в двух терминалах одновременно: обе будут писать
в один транскрипт.

## Ограничения

- Подключения claude.ai (Notion, Gmail, Linear и т. п.) привязаны к аккаунту. Во втором аккаунте их подключают заново.
- Проверено на Linux. На macOS токены хранятся в Keychain. После `/login` сверь `/status` в обоих терминалах.
- `~/.local/bin` должен быть в `PATH`. Если его там нет, скрипт предупредит.

## Разработка

```bash
claude plugin validate .   # манифест, маркетплейс и хуки
claude plugin test .       # tests/*.test.ts
claude --plugin-dir .      # запустить сессию с плагином из этой папки
```
